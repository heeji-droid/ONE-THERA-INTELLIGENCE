# 수집 데스크 계보

이 저장소는 **두 세션**으로 돌아간다.

- **처리 세션** — 케이스를 쓰고 반증 조건을 점검하고 뷰어를 발행한다. 고정이다.
- **수집 데스크** — 매일(13:00 KST)과 매주 금요일(17:00 KST) 수집해 커밋한다. 컨텍스트가 차면 교체된다.

데스크는 컨텍스트 한도(100만 토큰)에 다가가면 교체한다. **임계는 760K**이고, 하루 약 40K씩 오른다.

## 교체 순서 — 이 순서를 거꾸로 하면 열흘을 잃는다

1. 새 데스크를 만든다 (`create_session`)
2. 새 데스크가 **실제로 커밋·푸시하는 것을 확인한다** (이 파일에 자기 항목을 추가하는 것이 그 확인이다)
3. **그 다음에** 트리거를 옮긴다. `update_trigger`에는 대상 세션을 바꾸는 인자가 없으므로,
   새 데스크를 `persistent_session_id`로 하는 **새 트리거를 만들고** 기존 트리거는 `enabled=false`로 **끈다**
   — 지우지 않는다(실행 이력이 남아야 한다). 프롬프트를 옮길 때 **낡은 값을 같이 고친다**:
   파일명(`2026-q3` → `2026-q4`), 선례 범위(`0289~0301` → 현재), 케이스 수, egress 경과 일수
4. 이전 데스크는 그대로 둔다 — 지우지 않는다

**2026-09-06 ~ 09-16, 열흘 동안 수집이 끊겼다.** 데스크 I이 조용해진 것을 알아차리는 장치가 없었다.
(데스크 II → III 교체는 같은 날 안에 이어졌다 — 끊긴 것은 I → II 한 번이다.)

## 데스크가 바뀌어도 바뀌지 않는 것

1. **Tier는 실제로 읽은 문서가 정한다.** 발행사의 이름이 아니다 — NIQ·Circana·Euromonitor를 2차 인용으로 읽었으면 Tier 3이다.
2. **"찾지 못했다"는 "없다"가 아니고, "모른다"는 "비어 있다"가 아니다.**
3. **우리에게 유리한 근거일수록 더 엄격히 읽는다.**
4. **틀린 기록은 고치지 않는다.** 교정 기록을 새로 쌓는다 — 오차를 측정할 수 있어야 한다.
5. **note를 끝까지 쓴다.** 한계·미확인·출처의 이해관계를 note에 남긴다. 처리 세션은 그 note를 읽고 케이스의 문장을 좁힌다.
6. **같은 곳을 두 번 파지 않는다.** 두 번 실패한 경로는 방법을 바꾸거나 접는다.

  같은 교정이 같은 문서에서 두 번 났다 — **두 번 다 기억으로 적은 자리였다.**
