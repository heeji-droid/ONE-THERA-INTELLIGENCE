# docs/cases

**케이스 스터디 저장소.** 이 시스템이 축적하는 실체가 여기 쌓인다.

한 주제를 한 번 파고들면 한 개의 케이스가 남는다.
케이스가 100개 쌓이면 그것이 이 브랜드의 지적 자산이다.

```
YYYY-MM-DD-{slug}.md
```

## 최소 조건

```
· Atomic Insight 5건 이상
· 서로 다른 Tier 2개 이상
· FACT(관찰)와 INFER(해석)가 분리되어 있을 것
· 결론이 "기회 없음"이어도 된다 — 단, 반드시 이유를 쓴다
```

## 빈손도 케이스다

기회가 나오지 않은 케이스를 **지우지 않는다.**
"여기는 이미 봤고 비어 있었다"는 기록이 다음 사이클의 중복 탐색을 막는다.
`VERDICT: empty`로 남기고, **무엇을 어디까지 찾았는지**를 적는다.

## VERDICT

| 값 | 의미 |
|---|---|
| `opportunity` | 게이트 통과 → `docs/opportunities/`에 카드 생성 |
| `watch` | 신호는 있으나 게이트 미통과. 무엇이 부족한지 명시 |
| `empty` | 찾아봤으나 없음. 어디까지 찾았는지 기록 |
| `dead` | 있었으나 이미 닫힌 기회 (경쟁사 선점·규제 불가) |

## 템플릿

```markdown
# CASE {YYYY-MM-DD}: {주제}

**VERDICT**: opportunity / watch / empty / dead
**촉발**: {이 케이스를 연 이유 — coverage.py의 어느 결핍인가}
**초점 drive**: {}
**신규 인사이트**: {AI-id 목록}

## 무엇을 찾았는가 (Tier 1 → 4)
| Tier | id | 출처 | FACT | INFER | conf / infer |
|---|---|---|---|---|---|

## 찾지 못한 것
{어디를 봤고 무엇이 없었는지. 이 기록이 다음 사이클을 아낀다}

## 읽어낸 것
- **drive**: {}  ← 왜 원하는가
- **mechanism / trigger**: {}  ← 무엇이 행동으로 바꾸는가
- **trust**: {}  ← 무엇이 믿게 하는가
- **outcome**: {}  ← 도달하려는 상태

## 왜 지금인가
{촉발 요인 · 구조적인가 순환적인가}

## 판정 근거
{VERDICT를 그렇게 정한 이유. watch면 무엇이 부족한지 숫자로}

## 이 케이스가 남긴 것
- 커버리지 변화: {before → after}
- 다음 AGENDA: {이번에 드러난 결핍}
- 반증 조건: {이 판정이 뒤집히려면 무엇이 관찰되어야 하는가}
```
