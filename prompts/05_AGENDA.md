# 05 — AGENDA · 이번 사이클에 무엇을 볼 것인가

> 앞에 `00_MASTER.md`를 붙인다.
> 입력: `tools/coverage.py --agenda` 출력 + 오늘 날짜
> 출력: 이번 사이클의 수집 지시서 (마크다운)

**사람이 주제를 정하지 않는다.** 결핍이 정한다.
사람이 정하면 이미 관심 있는 것만 보게 되고, 저장소는 한쪽으로 기운다.

---

## 먼저 기계를 돌린다

```bash
python3 tools/coverage.py data/insights/*.jsonl
```

## TASK

### 1. 결핍을 읽는다

`coverage.py`가 낸 우선순위를 그대로 받되, **하나만 판단을 더한다**:

> 이 결핍은 **우리가 안 본 것**인가, 아니면 **정말 거기 없는 것**인가?

`blank`로 뜬 drive가 실제로 뷰티에 존재하지 않을 수도 있다.
이미 그 drive를 찾아본 케이스가 `docs/cases/`에 있는지 확인한다.
있고, 빈손이었다면 → 우선순위를 낮추고 다음 결핍으로 간다. **같은 곳을 두 번 파지 않는다.**

### 2. 초점 1개를 정한다

최우선 결핍 하나를 골라 **구체적인 탐색 질문**으로 바꾼다.

```
❌ "growth에 대한 자료를 찾는다"          — 검색할 수 없는 지시
✅ "스킨케어에서 '나아지고 있다'를 사용자가
    무엇으로 확인하는가 — 측정·기록·비교 행동을
    Reddit과 리뷰에서 찾고, 그 근거가 될 임상
    지표를 PubMed에서 확인한다"           — 검색 가능한 지시
```

### 3. 상시 비트를 배치한다

초점과 별개로 **매 사이클 도는 6개 비트**를 각각 1–2개 쿼리로 배치한다
([`06_AUTONOMOUS_LOOP.md`](../06_AUTONOMOUS_LOOP.md) 참조).

**Tier 4를 맨 앞에 둔다.** 소비자가 먼저 말하고 기관이 나중에 확인한다.
Tier 1부터 시작하면 이미 아는 것만 확인하게 된다.

### 4. 중복을 미리 차단한다

기존 저장소에서 이번 초점과 같은 `drive`를 가진 인사이트의 **출처 이름을 나열**하고,
"이번에는 이 출처들과 독립적인 것을 찾는다"고 명시한다.
같은 원본을 재인용한 기사는 새 출처가 아니다.

### 5. 성공 조건을 미리 쓴다

이번 사이클이 끝났을 때 **무엇이 있으면 성공인가**를 숫자로 적는다.
적어두지 않으면 수집을 언제 멈춰야 할지 알 수 없고, 무한히 훑게 된다.
